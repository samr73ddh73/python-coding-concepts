Array Patterns

👉
Two-Pointer Pattern

Use opposite or same-start pointers to avoid O(n²) nested loops.

  • Start from both ends for sorted arrays
  • Gap technique for position-based problems
  • Different speeds (tortoise/hare) for cycle detection
O(n) time O(1) space
🪟
Sliding Window

Maintain a window, expand right pointer, shrink left when needed.

  • Fixed size: advance both together
  • Variable size: shrink when condition invalid
  • Track data in HashMap for efficiency
O(n) time O(k) space
➕
Prefix Sum

Precompute cumulative sums for instant range queries.

prefix[i] = sum(arr[0..i-1]) rangeSum = prefix[r+1] - prefix[l]
O(n) precompute O(1) query
📍
In-Place Modification

Track write position instead of creating new arrays.

  • Keep pointer to next write position
  • Use swap or assignment
  • Works when output ≤ input size
O(n) time O(1) space
🔄
Sorting First Strategy

Sometimes sorting first enables better algorithms.

  • Two-pointer after sort for pairs
  • Intervals/merge problems
  • Cost: O(n log n) but enables O(n) solution
🗺️
HashMap Frequency Count

Count occurrences for O(1) lookups.

freq[num] = freq.get(num, 0) + 1 if num in freq: # O(1) check
Common pattern

Tree Patterns

🔴
PreOrder Traversal

Root → Left → Right

Process node BEFORE children. Best for:

  • Creating tree copies
  • Serialization/deserialization
  • Expression trees
🟢
PostOrder Traversal

Left → Right → Root

Get child results FIRST. Best for:

  • Height/depth calculation
  • Tree diameter
  • LCA problems
🔵
Level Order (BFS)

Process tree level by level with queue.

  • Shortest path in unweighted tree
  • Right/left view
  • Zigzag traversal
Queue-based
↔️
InOrder + BST

InOrder of BST gives sorted sequence!

  • Validate BST properties
  • Find k-th smallest
  • Check sorted order
🎒
Return Tuple from Recursion

Return multiple values to avoid recomputation.

def dfs(node): # return (is_valid, value) left_val, left_valid = dfs(node.left) # Use both in current node
📋
Complexity Analysis

Time: O(n) - visit each node
Space: O(h) recursion stack

  • Balanced: h = O(log n)
  • Skewed: h = O(n)

Graph Patterns

🔎
DFS vs BFS

Both O(V+E) but different space usage.

  • DFS: Recursion stack O(h)
  • BFS: Queue O(w)
  • Choose by problem, not time
🔁
Cycle Detection States

0 = White (unvisited)
1 = Gray (in current path)
2 = Black (fully processed)

If reach gray → cycle found!

📍
Multi-Source BFS

For "distance to nearest source":

  • Add ALL sources to queue first
  • Mark all visited
  • BFS discovers distances correctly
⚖️
Dijkstra's Must-Know

Shortest path with weights:

  • All edges non-negative only
  • Min-heap priority queue
  • O((V+E) log V)

For negative: use Bellman-Ford

🗺️
Topological Sort

For Directed Acyclic Graphs (DAGs):

  • DFS post-order + stack
  • Or Kahn's algorithm (in-degree)
  • O(V+E)
✅
Bipartite Check

2-colorable graph detection:

  • Color nodes as you traverse
  • Neighbors must have different color
  • Works with BFS or DFS

LinkedList Patterns

🐢
Floyd's Cycle Detection

Slow 1 step, Fast 2 steps:

  • No cycle: fast → None
  • Cycle: meet at node
  • O(n) time, O(1) space!
🎯
Cycle Start Location

After detecting cycle:

  1. Reset slow to head
  2. Move both 1 step
  3. Meet at cycle start

Math: dist(head→start) = dist(meet→start)

🔢
Remove Nth From End

Gap of n+1 technique:

fast ahead by n+1 Move both until fast.next = None slow lands BEFORE target
🪢
Dummy Node Pattern

Always use dummy when removing head:

dummy = ListNode(0) dummy.next = head # ... operations ... return dummy.next
🔄
List Reversal

Iterative approach:

prev = None while head: nxt = head.next head.next = prev prev = head head = nxt return prev
🏪
LRU Cache Construction

HashMap + DoublyLinkedList:

  • HashMap for O(1) access
  • LL for O(1) move/remove
  • Access: move to head

Binary Search Patterns

📏
Exact vs Boundary

Exact: while (left <= right)
Boundary: while (left < right)

  • Match returns if found
  • Boundary leaves at edge
🔄
Mid Calculation

Avoid overflow:

// Safe version: mid = left + (right - left) // 2 // Instead of: mid = (left + right) // 2
🔀
Rotated Array Key

One half ALWAYS sorted!

  • Identify sorted half
  • Check if target in sorted
  • Go to that direction
⛰️
Peak Element

Peak = element > neighbors

  • Compare nums[mid] with mid+1
  • mid < mid+1: peak right
  • Else: peak left/mid
🎯
Binary Search on Answer

When answer space is monotonic:

  • Define canDo(x)
  • Search answer range
  • Not the array itself
⏱️
Complexity Analysis

Standard: O(log n)

Variants:

  • + processing: O(n log n)
  • On answer: O(log ans * check)

Dynamic Programming Patterns

🤔
When DP Applies

Two must-haves:

  • Overlapping subproblems: Same computations repeated
  • Optimal substructure: Solution uses subproblem solutions

If both exist → DP works!

⬆️
Top-Down (Memoization)

Recurse from goal to base:

  • More intuitive
  • Cache results in dict
  • Risk: stack overflow
start from goal
⬇️
Bottom-Up (Tabulation)

Iterate from base to goal:

  • More efficient
  • Fill table iteratively
  • Easy space optimization
start from base
🏷️
State Definition

Define clearly what dp[i] means:

  • Prefix: ways/sum up to i?
  • Range: from i to j?
  • Capacity: using i items with w?
🔗
Recurrence Relation

Express dp[i] using smaller states:

dp[i] = f(dp[i-1], dp[i-2], ...) Base: dp[0], dp[1]
💾
Space Optimization

If only using previous row/column:

  • Use rolling array (1D instead of 2D)
  • Keep only needed values
  • Common in 2D DP problems

Interview Pro Tips

📝
Time Complexity Hierarchy
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)

n=1000: n² is still okay (1M ops)

🐛
Edge Cases to Test
  • Empty input
  • Single element
  • All same values
  • Already sorted/reverse sorted
  • Null/None checks
🎯
Problem-Solving Steps
  1. Understand completely
  2. Think of examples
  3. Brute force first
  4. Optimize iteratively
  5. Code carefully
  6. Test edge cases
💡
Common Optimizations
  • Sort first (enables two-pointer)
  • Hash maps (O(1) lookups)
  • Precomputation (prefix sums)
  • Space-time tradeoffs
🔍
Pattern Recognition

After solving, ask:

  • What pattern did I use?
  • Can it apply elsewhere?
  • What was the key insight?
  • Any better approach?
⏱️

  • 5 min: Test examples
  • Remaining: Optimize if time

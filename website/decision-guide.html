🌳 Algorithm Decision Guide

Quick flowcharts to choose the right algorithm for your problem

Array Problems

❓ Is the array sorted?
✓ YES
→ Consider Binary Search variants, Two-Pointer, or Sliding Window
✗ NO
→ Check if you need in-place modification or can use extra space
❓ Need in-place O(1) space?
✓ YES
→ Two-Pointer technique or track write position
✗ NO
→ Hash Map, Sorting, or Prefix Sum allowed
❓ Finding pairs/sum combinations?
✓ YES
→ Two-Pointer (sorted) or Hash Map (unsorted)
✗ NO
→ Check for range queries or subarray patterns

Tree Problems

❓ Is it a path problem (root to leaf)?
✓ YES
→ DFS PreOrder with backtracking. Track path as you go down.
✗ NO
→ Check if height/depth related
❓ Height, diameter, or balance related?
✓ YES
→ DFS PostOrder. Get results from children FIRST, then process.
✗ NO
→ Check if level-wise operations needed
❓ Level-wise operations?
✓ YES
→ BFS with Queue. Process nodes level by level.
✗ NO
→ Default to DFS (simpler recursion)
Traversal Order Best For When to Use
PreOrder Root → Left → Right Copies, Serialization Process node before children
InOrder Left → Root → Right BST validation, Sorted Node between children
PostOrder Left → Right → Root Height, Diameter, LCA Process children before parent
Level Order Level by level Level-wise ops, Shortest Queue-based horizontal scan

Graph Problems

❓ Shortest path?
✓ YES
→ Unweighted: BFS | Weighted (+): Dijkstra | Negative weights: Bellman-Ford
✗ NO
→ Check if cycle detection needed
❓ Detect cycle?
✓ YES
→ Directed: DFS with state (white/gray/black) | Undirected: DFS with parent tracking
✗ NO
→ Just traversal needed?
❓ Need to explore all nodes?
✓ YES
→ DFS if memory concern | BFS if level-wise needed
✗ NO
→ Topological sort or specific pattern
Algorithm Time Use Case Constraint
DFS O(V+E) Cycles, Components, Paths None
BFS O(V+E) Shortest path (unweighted) Unweighted only
Dijkstra O((V+E) log V) Shortest path (weighted) Non-negative weights
Bellman-Ford O(VE) Shortest (any weights) Slow, use only if needed

LinkedList Problems

❓ Cycle involved?
✓ YES
→ Floyd's Algorithm (slow & fast pointers). Time: O(n), Space: O(1)
✗ NO
→ Check if position/node removal needed
❓ Position-based (nth element)?
✓ YES
→ Two-Pointer gap technique. Gap of n+1 to land BEFORE target.
✗ NO
→ Check if modifying head itself
❓ Might remove head?
✓ YES
→ Use DUMMY NODE. dummy.next = head, return dummy.next
✗ NO
→ Simple traversal and modification

Binary Search Problems

❓ Array definitely sorted?
✓ YES
→ Binary Search applicable
✗ NO
→ Binary Search NOT applicable
❓ Looking for exact value or boundary?
✓ EXACT
→ while (left <= right), returns index or -1
✗ BOUNDARY
→ while (left < right), leaves left at boundary (first/last)
❓ Answer space binary-searchable?
✓ YES
→ BS on Answers. Define canDo() and search answer space, not array.
✗ NO
→ Standard or rotated array search

Dynamic Programming Problems

❓ Problem has overlapping subproblems?
✓ YES
→ DP is applicable. Define state and recurrence.
✗ NO
→ Divide & Conquer or Greedy might work
❓ Memoization or Tabulation?
✓ MEMO
→ Top-Down. More intuitive. Recurse from goal to base.
✗ TAB
→ Bottom-Up. More efficient. Build from base to goal.
❓ One or two dimensions?
✓ ONE
→ 1D DP array or recursive memoization
✗ TWO
→ 2D DP table (consider space optimization)
